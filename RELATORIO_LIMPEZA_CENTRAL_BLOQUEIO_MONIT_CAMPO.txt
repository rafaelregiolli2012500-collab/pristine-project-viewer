- POST /api/public/monit/admin/installations — listar | bloquear | desbloquear (usada pelo Admin Web, exige senha administrativa).
- GET /health — disponibilidade técnica.

- access_credentials: credencial de login (salt + hash, status, is_admin). Finalidade: login do MONIT.CAMPO e autenticação administrativa.

8. INSTALLATION ID
Implementação existente preservada (UUID em localStorage, chave monit.campo/CHAVE/installation_id). Não foi criado segundo identificador, nem alterado o formato. Não entra em backup/restauração dos dados operacionais.

9. OFFLINE
Falha, timeout, DNS, conexão recusada, 4xx/5xx e resposta inválida são tratados como "sem comunicação": o MONIT.CAMPO continua funcionando com a última autorização válida do cofre local e o login offline usa o cache de credenciais. Ausência de internet nunca bloqueia. Nova tentativa na próxima sincronização.

10. BLOQUEIO
Admin Web → bloquear → status = bloqueada no banco. Na próxima consulta (login ou sincronização periódica), o aplicativo recebe "bloqueada", atualiza o cofre local, encerra a sessão, impede novo login e mostra a mensagem de bloqueio. Nenhum dado operacional, configuração, backup ou Installation ID é apagado.

11. DESBLOQUEIO
Admin Web → desbloquear → status = autorizada. Na próxima consulta o aplicativo atualiza o cofre e volta a permitir o acesso normalmente.

12. SEGURANÇA
- SUPABASE_SERVICE_ROLE_KEY somente no servidor (import dinâmico dentro dos handlers); nunca em VITE_*, no bundle ou no Electron.
- Autenticação administrativa por senha verificada no servidor (PBKDF2-SHA256, 100000 iterações); somente salt + hash no banco.
- Rate limit por origem e limite de corpo (8 KB) preservados; timeout de 8 s; validação estrita do installation_id (UUID).
- Electron mantido com contextIsolation: true, nodeIntegration: false, sandbox: true; nenhuma ponte privilegiada adicionada.
- VITE_MONIT_API_URL preservado para apontar o .exe à API externa.
