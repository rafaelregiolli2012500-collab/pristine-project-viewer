   Aplicação -> getInstallationAccess() -> Supabase JS -> HTTPS

             -> autorizada = permitido | pendente = negado | bloqueada = negado

5) INSTALLATION ID
   Mecanismo preservado integralmente: UUID aleatório gerado uma única vez e
   guardado em monit.campo/CHAVE/installation_id (armazenamento local),
   independente dos dados operacionais e do backup/restauração.
   Nenhum novo identificador foi criado.

6) SUPABASE UTILIZADO
   O projeto oficial já configurado no projeto (variáveis de ambiente
   VITE_SUPABASE_URL / VITE_SUPABASE_PUBLISHABLE_KEY / VITE_SUPABASE_PROJECT_ID).
   Nada foi trocado, migrado ou recriado. Somente a chave publicável está no
   cliente; nenhum segredo administrativo no frontend, preload, main ou .exe.

7) RPC UTILIZADA
   public.monit_installation_access(p_installation_id, p_name) — devolve
   apenas name e status. Não aceita parâmetro de status.

8) COMPORTAMENTO OFFLINE
   Rede indisponível, DNS, timeout, conexão recusada, 4xx/5xx ou resposta
   inválida = SEM COMUNICAÇÃO (nunca BLOQUEADO). Vale o último estado válido
   do cofre local; sem estado válido conhecido, acesso permanece negado.

9) PERIODICIDADE
   Um único timer de 10 minutos (600000 ms). Sem heartbeat, polling duplicado,
   WebSocket, Realtime ou telemetria.

10) TESTES REALIZADOS E RESULTADOS
   a) npm run test:access (vitest) — 12 testes, TODOS PASSARAM:
      - instalação nova -> pendente -> acesso negado
      - autorizada -> acesso permitido
