2. INSTALLATION ID
Implementacao unica em src/lib/access/local.ts: UUID aleatorio persistido na
pasta CHAVE (localStorage). Nao existe mais nenhum segundo identificador; o
processo principal do Electron nao gera nem grava identidade.

3. CONEXAO EXTERNA
Camada unica src/lib/access/api.ts. Base = VITE_MONIT_API_URL (nenhuma URL
inventada; valor vazio no .env.example). No Electron a origem app://monit.campo
nunca e usada como API. Nenhum token, senha ou service role no frontend.

4. ENDPOINT USADO PELO EXE
POST {VITE_MONIT_API_URL}/api/public/monit/installations
corpo: { installation_id: UUID, name: "Instalacao" }
resposta: { ok: true, status: "pendente" | "autorizada" | "bloqueada" }
Nenhum dado operacional e enviado.

5. AUTORIZADA : funcionamento normal; status salvo no cofre local existente.
6. PENDENTE   : comportamento local existente preservado (nao equivale a bloqueio).
7. BLOQUEADA  : sessao encerrada e acesso impedido, com a mensagem existente de
                instalacao bloqueada. Nenhum dado, backup ou configuracao apagado.
8. OFFLINE    : timeout, DNS, conexao recusada, 500/502/503 sao tratados em
                api.ts como "sem comunicacao"; o aplicativo segue com o ultimo
                estado valido do cofre. Sem tela branca e sem bloqueio de startup.
9. SINCRONIZACAO: unico timer existente em useAuth.ts (10 minutos). Nenhum
                segundo timer, heartbeat, polling, WebSocket ou Realtime.
10. ROTAS LOCAIS: src/routes/api/public/monit/* permanecem como Central local/
                legado do build web e nao foram apagadas. Com VITE_MONIT_API_URL
                configurado, api.ts prioriza a URL externa; no Electron, sem essa
                variavel, nao ha base HTTP alguma, portanto o .exe nunca chama as
                rotas locais.
11. ADMIN     : credencial ADMIN e PBKDF2 preservados; nenhuma senha em texto puro.
12. ELECTRON  : carrega app://monit.campo/index.html a partir de dist-electron,
                com contextIsolation: true, nodeIntegration: false, sandbox: true,
                webSecurity: true e asar habilitado.
13. ICONE     : script "icons" (scripts/make-icons.mjs) gera build/icon.ico e
                build/icon.png a partir de public/icon.png. Nenhuma lib nova.

16) VALIDAÇÃO FINAL — LOGIN LOCAL + STATUS REMOTO (14/09/2026)
================================================================
- useAuth.ts PRECISAVA de alteração: o login chamava
  POST /api/public/monit/auth/check enviando { installation_id, password },
  ou seja, a senha do usuário trafegava para a Central. Reescrito.
- auth/check: era usado SOMENTE pelo login do useAuth.ts (o Admin Web usa
  apenas /admin/installations). Dependência removida do cliente, a constante
  ACCESS_ENDPOINTS.authCheck foi excluída de protocol.ts e a rota
  src/routes/api/public/monit/auth/check.ts foi apagada.
- Senha: 100% local. Conferência exclusiva por verifyLocalPassword()
  (cofre AES-GCM + PBKDF2 100000 iterações, credencial inicial ADMIN em
  salt+hash). Nenhum endpoint remoto recebe campo "password" a partir do
  .exe. Sessão local, ADMIN e funcionamento offline preservados.
- Status remoto: consulta única em consultarStatus() usando o mesmo e único
  endpoint POST {VITE_MONIT_API_URL}/api/public/monit/installations com
  { installation_id: UUID, name }. Usada no login e no timer já existente
  (10 min). Nenhum segundo timer, retry ou mecanismo de bloqueio criado.
  bloqueada => encerra sessão e mostra a mensagem existente;
  autorizada => uso normal; pendente => uso local normal;
  sem comunicação (timeout/DNS/recusa/500/502/503) => último estado válido
  do cofre local, sem bloquear o aplicativo.
- Installation ID: continua único, UUID persistente em
  src/lib/access/local.ts. Nenhum identificador novo.
- VITE_MONIT_API_URL: única origem da URL externa, lida somente em
  src/lib/access/api.ts. Como é variável de BUILD, ela precisa existir no
  ambiente/arquivo .env NO MOMENTO de `npm run build:electron`; definir a
  variável depois de empacotar NÃO chega ao .exe (seria necessário
  reempacotar). .env.example mantém `VITE_MONIT_API_URL=` vazio.
- Testes executados: tsgo --noEmit OK; npm run build:electron OK;
  npm run build OK. npm run lint continua reportando apenas divergências
  de formatação Prettier preexistentes. NÃO foram executados testes do
  instalador Windows nem testes automatizados de acesso (não existem no
  projeto).

17) ULTIMA AUDITORIA — REMOCAO DA DEPENDENCIA DE AUTH/CHECK (15/09/2026)
================================================================
- auth/check AINDA ERA UTILIZADO? Nao. A rota
  src/routes/api/public/monit/auth/check.ts ja havia sido removida na
  validacao anterior (item 16), junto com ACCESS_ENDPOINTS.authCheck.
  Esta auditoria confirmou por busca que nao existe mais nenhum arquivo
  nem nenhuma referencia a "/api/public/monit/auth/check", "authCheck"
  ou "AuthCheckResponse" em todo o src/.
- REFERENCIAS ENCONTRADAS nesta auditoria:
  * src/lib/access/db.server.ts: activeDigests() (sem nenhum consumidor —
    era usada somente pelo antigo auth/check) => REMOVIDA.

    /api/public/monit/admin/installations (Admin Web).
  * src/routes/api/public/monit/installations.ts usa apenas db().

    login, entregue somente a verifyLocalPassword(). Nenhum envio remoto.
  * src/lib/access/api.ts: nenhuma referencia a credenciais.
- ROTA REMOVIDA OU MANTIDA: removida (no item 16); nesta auditoria apenas

  hash, salt ou credentials em nenhuma requisicao do cliente.
- LOGIN LOCAL: 100% local via verifyLocalPassword() (cofre AES-GCM +
  PBKDF2 100000 iteracoes, credencial inicial ADMIN em salt+hash), com
  sessao local e funcionamento offline preservados. Nenhum segundo sistema
  de autenticacao, segundo Installation ID ou segundo timer foi criado.
- CENTRAL EXTERNA: controla exclusivamente o estado da instalacao

- ELECTRON: app://monit.campo usa VITE_MONIT_API_URL somente para consultar
  o status da instalacao; nao existe (nem pode existir) chamada a
  auth/check, pois a rota e a constante nao existem mais no codigo.
