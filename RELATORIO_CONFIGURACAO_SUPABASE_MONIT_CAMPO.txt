7. TABELA public.installations
------------------------------
id uuid pk default gen_random_uuid()
installation_id text not null unique
name text not null
status text not null default 'pendente'
created_at timestamptz not null default now()
updated_at timestamptz not null default now()
Status validos: pendente | autorizada | bloqueada.

8. RPC
------
public.monit_installation_access(p_installation_id, p_name)
Retorna somente name e status da propria instalacao consultada.
O aplicativo consulta exclusivamente por essa RPC
(src/lib/access/remote.ts — unica chamada de rede do controle remoto).

9. RLS / SEGURANCA
------------------
Testado diretamente contra o novo projeto com a Publishable Key:
  RPC   monit_installation_access ......... 200 (funciona)
  SELECT direto em installations .......... 401 permission denied
  INSERT direto ........................... 401 permission denied
  UPDATE direto ........................... 401 permission denied
  DELETE direto ........................... 401 permission denied
O cliente nao le nem altera a tabela; nao recebe outras instalacoes,
dados administrativos, credenciais ou informacoes internas.

10. REGRA PENDENTE / AUTORIZADA / BLOQUEADA
-------------------------------------------
autorizada -> permite entrar   |   pendente -> nega   |   bloqueada -> nega
Pendente nunca e interpretado como autorizado.

11. COMPORTAMENTO OFFLINE
-------------------------
Falha de comunicacao (offline, DNS, timeout 8s, conexao recusada,
400/401/403/408/429/500/502/503, resposta invalida) e tratada como
"sem comunicacao" e NUNCA como bloqueio. Vale o ultimo estado valido
guardado no cofre local criptografado. Sem nenhum estado valido
conhecido, o acesso permanece negado.

12. CONSULTA PERIODICA
----------------------
Uma unica rotina, em src/hooks/useAuth.ts, com um unico setInterval de
10 minutos, atualizando somente o estado de autorizacao. Sem polling
duplicado, sem heartbeat remoto, sem timers concorrentes.

13. LOGIN LOCAL
---------------
Preservado integralmente: 1) autorizacao remota -> 2) se autorizada ->
3) login local (PBKDF2, senha nunca sai do computador) -> 4) operacao.
Nenhum usuario, senha ou ADMIN foi criado, removido ou alterado.

14. INSTALLATION ID
-------------------
Mecanismo unico e inalterado (src/lib/access/local.ts), UUID gerado uma
unica vez, persistente em armazenamento local, fora do backup
operacional. Teste real: fechar/reabrir manteve o mesmo identificador
85e1ff24-... Nao existe outro gerador de Installation ID no projeto.

sandbox: true, webSecurity: true. Nenhum secret em main.cjs, preload.cjs,
